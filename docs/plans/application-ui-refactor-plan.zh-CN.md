# Codex 梦幻皮肤全软件 UI 重构总纲

## 1. 文档状态

| 项目 | 内容 |
| --- | --- |
| 范围 | 整个 Windows 管理器 |
| 平台 | WinUI 3，Windows 10/11 |
| 当前阶段 | 扁平化工作台与完整原生 Codex 隔离页面已实现 |
| 工作模式 | 概览、主题、诊断、设置 |
| 行为原则 | 保留服务、数据、安全和部署契约，重构信息架构与界面 |

主题编辑器的详细工具、隔离预览和 schema 规划继续由
[`theme-studio-ui-plan.zh-CN.md`](theme-studio-ui-plan.zh-CN.md)
负责；本文档是它的上层全软件规划。

## 2. 重构目标

- 把软件从多个独立长页面统一为一个专业的 Windows 创作工具。
- 让概览负责运行状态，主题负责创作，诊断负责排障，设置负责管理。
- 使用一致的工作台栏、间距、命令、表面、滚动和响应式规则。
- 保留现有主题目录、草稿、历史、CDP、托管、启动和版本检查行为。
- 同时支持浅色、深色和高对比度，不建立平行的自定义控件体系。
- 逐步把超大页面拆分为可维护的工作区状态和复用控件。

## 3. 视觉与交互方向

### 3.1 视觉命题

安静、专业的 Windows 创作工具。主题内容是主视觉，导航和系统状态保持低噪声。

### 3.2 内容结构

1. 应用壳提供稳定的一级导航和品牌识别。
2. 概览提供当前连接、主题和管理器状态。
3. 主题提供三栏创作工作台。
4. 诊断提供环境健康与端口检查。
5. 设置提供分区式管理表单。

### 3.3 交互命题

- 模式切换由顶部工作条控制，内容在同一工作台内替换。
- 选择、加载和状态变化使用短促、可预测的系统反馈。
- 不增加纯装饰动画；后续只在工作区切换和预览状态变化中使用过渡。

## 4. 全局应用壳

应用使用单窗口沉浸式主题工作台，不再使用 `NavigationView`：

- 顶部 64px 工作条显示 `OPEN CODEX SKIN`、`Theme Studio`、当前上下文和模式操作。
- 概览、主题、诊断和设置从顶部切换，不占用常驻全局左栏。
- 默认启动直接进入主题工作台。
- 各模式不再重复显示大标题、副标题或页面 Hero。
- 内容统一使用低噪声主题平面，不再铺设大面积低透明度背景图。
- 继续使用 Mica 作为窗口级长期背景。
- 标题栏保持 Windows 拖动和标题按钮行为。
- 窄窗口隐藏次要上下文和诊断快捷入口，保留首页、主题与设置。

## 5. 页面职责

### 5.1 概览

职责：回答“现在能否安全应用主题”。

- 首要区域显示主题引擎状态、详情、应用主题和重新检查。
- 主题参考图只作为当前主题的视觉锚点。
- 次级区域显示原生外壳和主题资产状态。
- 免费软件声明和安全启动说明位于页面尾部。
- 宽屏显示图文双栏；窄屏隐藏非必要主题图，状态改为单列。

### 5.2 主题

职责：完成主题选择、编辑、预览、保存和应用。

- 左侧使用“主题库 / 编辑工具”双态侧轨，默认打开十二项编辑工具。
- 中间为主题隔离预览。
- 右侧为收窄后的当前工具操作台。
- 详细实施继续遵循主题工作室子规划。

### 5.3 诊断

职责：回答“问题出在环境、资源、连接还是端口”。

- 左侧环境健康区汇总包身份、主题资源和 Codex 连接。
- 右侧端口工作区检查受管回环端口。
- 刷新诊断位于环境健康轨内部，不额外占用页面级工具条。
- 危险进程操作继续要求重新验证和确认。
- 中等宽度以下改为上下两段，不压缩端口内容。

### 5.4 设置

职责：管理应用自身，不直接编辑主题。

- 左侧分区轨道展示常规、自动化、更新和关于。
- 右侧统一承载应用外观、存储、自动托管、开机启动和版本来源。
- 表单使用分组表面和分隔行，不使用独立卡片堆叠。
- 中等宽度以下隐藏分区轨道，把内容宽度还给表单。

## 6. 共享设计系统

第一阶段已建立以下共享资源：

- `StudioPaneBrush`：导航、目录和辅助区域表面。
- `StudioSurfaceBrush`：长时间显示的工作区分组表面。
- `StudioGroupStyle`：统一分组容器。
- `WorkspaceTitleStyle`：兼容仍需局部标题的工作区。
- `WorkspaceSubtitleStyle`：统一局部分区说明。
- `SectionLabelStyle`：分区和工具组标签。
- `SettingsRowStyle`：设置行的最小尺寸。

共享资源必须同时提供浅色、深色和高对比度值。

## 7. 响应式规则

| 宽度 | 应用壳 | 工作模式 |
| --- | --- | --- |
| 1440 及以上 | 完整顶部操作条 | 270px 左轨、弹性预览、340px 右轨 |
| 1120–1439 | 隐藏上下文副标题 | 240px 左轨、弹性预览、320px 右轨 |
| 770–1119 | 隐藏次要顶部操作 | 220px 左轨、弹性预览、300px 右轨 |

当前应用最小窗口仍为 770×680。后续若降低最小宽度，需要先完成主题工作台的抽屉式操作台。

## 8. 状态和代码结构

第一阶段保持页面代码隐藏和现有服务，不引入形式化 MVVM。后续按收益拆分：

- `Controls/AppWorkspaceHeader`
- `Controls/StatusSummary`
- `Controls/SettingsGroup`
- `Controls/ThemeLibraryPane`
- `Controls/CodexPreviewHost`
- `ViewModels/ThemeWorkspaceState`
- `ViewModels/DiagnosticsState`

拆分遵循“行为不变、只移动职责”，不改变公开 schema、文件目录、CDP 安全校验或部署方式。

## 9. 分阶段实施

### 阶段一：扁平化单工作台

状态：已完成。

- 移除 `NavigationView` 和重复页面标题。
- 建立顶部品牌操作条和共享设计资源。
- 将概览、主题、诊断和设置改为同一工作台的四种模式。
- 建立四页响应式规则。
- 更新中英文资源与源契约测试。

### 阶段二：真实隔离预览

状态：原生完整页面 fixture 已完成，并已按用户提供的 Codex Home 截图校准为 1922×1034 固定设计画布、275px 侧栏和 906×164 双层输入器；WebView2 DOM 对照实现待实施。

- 已建立无网络原生 Codex Desktop fixture，覆盖窗口工具栏、侧栏、首页、任务、输入区和设置；Home 以用户截图为唯一基准，页面整体通过 Viewbox 等比缩放，避免在窄预览区把真实桌面结构挤成后台表单。
- 已实现首页、任务、设置切换，固定模拟回复和互动重置。
- 后续建立 WebView2 DOM fixture，用于提高与 Electron CSS/DOM 的一致性。
- 支持主页、任务、设置、菜单和悬浮窗口。
- 支持与真实 Codex 相似但无副作用的直接互动。
- 支持翻译、无分隔线模式和设置页验证。

## 10. 验收标准

### 功能

- 四个工作模式均可从导航轨进入。
- 原有保存、应用、诊断、托管、启动和版本检查行为不变。
- 页面切换和窗口调整不丢失持久化设置。

### 视觉

- 四个模式使用一致工作台栏、间距和表面。
- 主题预览仍是全软件最强视觉区域。
- 不出现卡片拼贴式仪表盘。
- 770px 最小宽度下主要操作仍可访问。

### 可访问性

- 导航、命令、开关、列表和链接可通过键盘访问。
- 图标按钮具有本地化自动化名称。
- 高对比度下不依赖背景色表达状态。

### 验证

- 软件级源契约测试通过。
- 完整 Windows 回归通过。
- x64 Release 构建为零警告、零错误。
- 便携版本启动后具有非零主窗口句柄并持续响应。
- 自动化权限可用时，逐页执行导航和响应式运行验收。
