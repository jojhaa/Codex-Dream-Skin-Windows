# Codex Kanna Blue Skin

Apply a reversible renderer skin through Chromium DevTools Protocol while launching the official Store-installed Codex executable. Never replace or take ownership of files under `WindowsApps`.

## Workflow

1. Prefer the packaged `app/CodexDreamSkin` manager. Apply the saved theme once, then optionally enable **Settings > Theme ordinary Codex launches automatically** after explaining that ordinary Codex is restarted and unsent input can be lost. The native manager registers a Windows `StartupTask`, remains single-instanced in the background, dynamically identifies the current Store-signed Codex package, and relaunches an ordinary no-CDP session through the bounded loopback theme ports.
2. Keep `scripts/install-dream-skin.ps1` and `scripts/start-dream-skin.ps1` as the explicit legacy/manual path. Add `-RestartExisting` only when the user authorized restarting an already-open Codex app. Without the manager's opt-in ordinary-launch takeover, the stock Codex shortcut still does not supply the required CDP launch flags.
3. Run `scripts/verify-dream-skin.ps1 -ScreenshotPath <absolute-path>` after launch. Treat a missing global portrait background, hero, native composer, sidebar skin, or injection marker as failure. The native suggestion count is responsive and may be two to four.
4. Inspect the screenshot against `references/qa-inventory.md`. Verify both the home screen and a normal task before signing off.
   Use `node scripts/injector.mjs --inspect --port <port>` to inventory live controls and stable selectors when a Codex update changes the renderer DOM.
5. Run `scripts/restore-dream-skin.ps1` for live removal. Add `-Uninstall` to delete shortcuts; add `-RestoreBaseTheme` when the user also wants the pre-install config backup restored.
