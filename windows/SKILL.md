# Codex Kanna Blue Skin

Apply a reversible renderer skin through Chromium DevTools Protocol while launching the official Store-installed Codex executable. Never replace or take ownership of files under `WindowsApps`.

## Workflow

1. Run `scripts/install-dream-skin.ps1` once to set the matching official base colors and create launch/restore shortcuts. If Codex is already open and only the managed runtime or shortcuts are stale, run it with `-RepairLauncher`; this refreshes the launcher without touching `config.toml` or restarting the app.
2. Run `scripts/start-dream-skin.ps1`. Add `-RestartExisting` only when the user authorized restarting an already-open Codex app. After a full exit, reopen with the installed `Codex Kanna Blue Skin` shortcut; the stock Codex shortcut does not supply the required CDP launch flags.
3. Run `scripts/verify-dream-skin.ps1 -ScreenshotPath <absolute-path>` after launch. Treat a missing global portrait background, hero, native composer, sidebar skin, or injection marker as failure. The native suggestion count is responsive and may be two to four.
4. Inspect the screenshot against `references/qa-inventory.md`. Verify both the home screen and a normal task before signing off.
   Use `node scripts/injector.mjs --inspect --port <port>` to inventory live controls and stable selectors when a Codex update changes the renderer DOM.
5. Run `scripts/restore-dream-skin.ps1` for live removal. Add `-Uninstall` to delete shortcuts; add `-RestoreBaseTheme` when the user also wants the pre-install config backup restored.

## Guardrails

- Preserve the official executable, package signature, user threads, pets, plugins, and authentication state.
- Never create or auto-run a hidden PowerShell tray shortcut. Install only the visible launch and restore shortcuts; keep the optional tray script manual and require an explicit user request before running it.
- Do not use the reference image as a fake whole-window UI screenshot. It may be used as a CSS wallpaper and cropped hero/polaroid asset, but every visible control must remain a live Codex control.
- Carry the portrait through the main work surface as a low-contrast blue-white background with a restrained global veil and local glyph-level readability protection. Never solve task readability with an almost-opaque full-canvas porcelain mask: cap the task veil at 56% on the reading side and taper it to 12% over the portrait, render the same portrait inside the sidebar beneath a 58% to 42% veil, and let empty task and workspace-panel regions reveal recognizable stage and portrait detail. On the home screen, use a continuous soft-focus porcelain band behind the native suggestion row so the subject is not fragmented between cards; keep every button and label intact.
- Keep the editorial home hero at exactly half of its native hero-and-suggestions stage height on both wide and compact layouts; verify the computed ratio instead of relying on a viewport screenshot crop.
- Detect the native settings route independently from home and task routes. Treat it as one continuous portrait canvas: cap the full settings veil at 42%/28%/16%/6%, leave the empty native header fully transparent and unmasked, suppress the decorative `app-shell-main-content-top-fade` that otherwise paints a 16px white seam, make the nested settings surface transparent and unblurred, and place native setting groups on 20% to 8% single-layer glass with no shadow. Theme the structural search shell, selected navigation row, dividers, and native dropdown buttons without replacing their controls; require recognizable portrait detail through the canvas and option groups.
- Detect the settings route from language-independent structure (a sidebar link, nested main surface, and absent task composer); never match localized labels such as “返回应用” or “Back to app”.
- Detect Plugins, Sites, and Pull Requests as one structural utility route through their full-height native surface and sticky input band, never through localized page titles. Clear the native opaque page root, hide its top fade, and use one 18%/14%/10%/6% portrait canvas, a 30% to 12% sticky tool band, and 24% to 10% search/control glass. Keep native rows, tabs, filters, plugin actions, search behavior, and scrolling intact; in dark mode use the matching 42%/32%/24%/18%, 42%/18%, and 48%/22% hierarchy.
- Keep Floating Chat distinct from ordinary dialogs. Detect its `_floatingSurface_` structure, use 42% to 18% portrait glass with 5px blur, and give its real composer the same 24% to 10% utility control layer without a white inset ring. Follow the dark 42%/18% and 48%/22% tokens while preserving chat history, window controls, typing, and send behavior.
- Keep the watcher reload-safe: reload the current payload from disk on every renderer load and reapply it when the installed marker, state, style, chrome, or structurally detected settings/utility class is missing.
- Follow Codex's native `html.electron-dark` state for dark mode and keep route detection language-independent; never spoof a theme class or depend on localized System/Light/Dark labels. Use one "midnight portrait glass" system rather than flattening the app to black: sidebar 74% to 56%, home 64%/50%/34%/18%, task 68%/54%/38%/22%, composer 62%/44%/28%/14%, Settings 46% to 22%, assistant/resource cards 42% to 18%, summary 42% to 18%, and workspace panels 44% to 20%. Preserve recognizable portrait detail, light text, semantic status colors, native focus states, and zero white flashes across Home, Task, Settings, overlays, and panels.
- Treat language switching and renderer reload as dark-mode persistence tests: the native `electron-dark` class, `color-scheme: dark`, dark tokens, injected state/style/chrome, and structurally detected route class must all survive without restarting Codex.
- Treat the native sidebar as a compact editorial navigation system: preserve every project/task action, distinguish expanded projects from the active task, indent task rows beneath their project, and verify active-row text contrast instead of applying one generic pale hover style to every row. Force real `group/folder-row` project controls, `cursor-grab` task shells, and their nested explicit task buttons to remain `pointer-events: auto`; clear native `inert` only from task listitems containing those real buttons, and restore it on cleanup while the native disabled class remains. Require zero inert visible tasks plus computed interactivity and `elementFromPoint` center-hit coverage for every visible project/task row, then exercise one native expand/collapse cycle and a real switch to a different task and back before signoff. A programmatic mouse dispatch without a matching hit target is not evidence of interaction.
- Preserve whole-window continuity: use one soft light direction across sidebar, task background, cards, and composer; avoid simultaneous scanlines, dashed rails, confetti marks, repeated pill borders, or mismatched elevation that visually tears the app into unrelated layers.
- Keep the sidebar and main canvas visually continuous: remove the sidebar edge, main/header separator stack, and processed-turn rule; retain the native task-jump rail as an 8×2px ice-blue signal track over a soft 34% glass capsule, with an 18×3px glowing current marker and unchanged navigation behavior. In compact layouts the resting/current markers may reduce to 7px/15px without becoming pale dots.
- Treat task-jump activity previews as rich light-glass tooltips rather than ordinary navy labels: remove the dark outer shell, use deep-blue titles and ink-blue summary/file metadata, and anchor the card to the signal track with a 3px inset blue edge instead of a clipped white rim. Require every visible text run to maintain at least 4.5:1 contrast against the preview surface, and carry the same edge treatment into the native dark branch. Use `node scripts/injector.mjs --hover-point <x,y> --port <port> --keep-overlay` when the rail button has no accessible text label.
- Detect the native output/source summary through its `summary-panel-item` structure rather than localized headings. Replace its opaque dropdown fill with an 18% to 6% portrait-first layer over an 8% fallback, cap backdrop blur at 2px, keep section toggles as unboxed deep-blue labels, reserve compact chrome for the trailing add buttons, and verify source rows remain readable over recognizable portrait detail.
- Treat native account, project, settings, and option menus as low-fog portrait glass through the language-independent `role="menu"` and `role="listbox"` structures. Use a 26% to 10% light layer over a 6% fallback with 4px blur, and a 42% to 20% dark layer over an 8% fallback with 5px blur; clear direct nested native fills, keep hover layers below 34%, and preserve the original menu items, keyboard focus, usage links, settings action, pet action, and sign-out behavior.
- Theme `diffs-container` through its public `--diffs-*` and `--codex-diffs-*` variables, then inject the dedicated `codex-dream-skin-diff-shadow-style` into every open component Shadow DOM. Follow the native color-scheme branch: retain the light 18%/12%/8% portrait-first hierarchy, and use `:host-context(html.electron-dark)` for dark 36%/24%/16% surfaces. Keep file headers, folded-context strips, gutters, and code rows translucent; preserve semantic addition/deletion colors; and prevent native or generic code rules from restoring opaque surfaces. Reapply the Shadow DOM style during every ensure cycle because diff virtualization can replace the component independently of the document tree.
- Detect the integrated bottom panel through `.terminal.xterm`, never localized terminal labels. Clear the native outer, toolbar, Electron-theme, viewport, and screen fills; retain one 8% fallback with an 18% to 6% gradient and no more than 2px blur. Preserve terminal tabs, resizing, scrolling, ANSI semantics, selection, and dark monospaced readability.
- Treat blank task gutters and the terminal's unused canvas as part of the portrait composition, not as white utility space. Verify the task mask tokens and the actual computed main background so transparent child panels cannot accidentally reveal a near-white parent layer.
- Keep task resource summaries and user-message bubbles translucent: use one borderless, shadowless low-opacity porcelain layer so the portrait remains recognizable. Keep nested file rows fully transparent outside hover and do not blur the portrait beneath user messages; never stack an outlined outer bubble around the native message content.
- Render assistant prose on the same single-layer glass used by native task resource summaries: reuse the shared 18% to 6% thread-card tokens, 3px backdrop blur, zero border/shadow, and restrained 12px radius directly on each native assistant markdown block. Do not add a feathered reading pseudo-layer, and exclude user-message markdown so separate chat roles remain intact.
- Treat native `[data-testid="exec-shell-body"]` output as a dark technical island even in light mode. Use the shared indigo console surface with ice-white default text, separately readable muted/link/success/warning/error colors, and a cyan scrollbar; override descendant light-theme foreground utilities that would otherwise render dark-on-navy. Require every populated text run to maintain at least 4.5:1 contrast without changing shell expansion, selection, scrolling, or command semantics.
- Keep home suggestions genuinely translucent by blurring the full native suggestion band before layering lighter glass buttons. Replace native suggestion glyphs only through non-interactive CSS masks on the existing icon containers, and verify every real button, sequential index, label, and click target remains intact.
- Treat the New Task route as a portrait canvas rather than an empty porcelain page. Cap the full-canvas veil at 42%/28%/16%/6%, keep the native header on a 52% to 20% light glass, and reduce the suggestion band/cards to 10% to 4% and 36% to 20% layers with no heavy white inset. Theme the structural `_homeUtilityBar_` at 34% to 16% and its native project button at 28% to 12%, then use the shared 48%/32%/18%/6% composer taper and clear any native dock fade. Reject near-white parent layers even when the child composer is technically translucent.
- When adding portrait imagery inside the task composer, render it as a softly masked right-side pseudo-layer rather than a bordered thumbnail or a hard-edged background layer. Keep the typing region on a readable 48% to 6% glass taper, preserve all native controls, clear the native `bg-gradient-to-t` dock fade, forbid white inset rings, and verify both the mask and portrait asset are active.
- Treat the native populated composer attachment/change queue (`_attachmentsDefault_`) as a text-protected portion of the existing composer, not as another opaque card. Keep the queue on 28% to 10% light glass (36% to 16% dark), force filenames, actions, glyphs, and muted metadata to fully opaque deep-blue/ice-white tokens, and use only a restrained glyph shadow to survive portrait highlights. Preserve row actions, removal, guidance controls, scrolling, and the empty-queue composer height.
- Treat native queued follow-up messages as a separate above-composer surface. Distinguish their `vertical-scroll-fade-mask` through the combined `max-h-[30dvh]`, `gap-px`, and `px-3` structural traits; do not confuse it with the activity rail's `max-h-[min(70vh,40rem)]` list or depend on localized labels. Use fully opaque deep-blue/ice-white text plus restrained 36% to 16% light glass or 40% to 20% dark glass. Explicitly reset nested `_markdownContent_` padding, radius, background, blur, and conversation line height because the native queue clips the formatted text to one line; require at least 95% of the glyph box to remain inside the line viewport. Preserve drag ordering, steer/retry, delete, overflow actions, warning semantics, and the native row-opacity animation.
- Attach the "选择项目" treatment to Codex's real project-selector toolbar and keep the current project button clickable; never draw a disconnected replacement.
- Keep decorative layers `pointer-events: none` and keep real buttons, navigation, and composer above them.
- On app updates, rerun install and launch; the scripts discover the current Appx package dynamically.
- If port `9335` is occupied, choose another port consistently for start, verify, and restore.
- Keep the injection daemon running for navigation/reload resilience. Its state and logs live under `%LOCALAPPDATA%\CodexDreamSkin`.
